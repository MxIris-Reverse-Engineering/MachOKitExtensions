摘要

CPlusPlusSymbols 模块新增一个按镜像建索引的 store CPlusPlusClassIndexStore，从镜像的数据里读 Itanium C++ ABI 的运行时类型信息（RTTI，即 std::type_info 对象）和虚函数表（vtable），不依赖符号表。它给出三样东西：

  • 类（CPlusPlusClass）：镜像里每个有 typeinfo 的类，名字取自 typeinfo 里的名字串，符号被剥离的类也找得到；带直接基类，以及每个基类的偏移、是否虚继承、是否 public，基类可能在别的镜像里。
  • 虚函数表（CPlusPlusVirtualTable）：主表与多重继承、虚继承下的副表，每张表的 offset-to-top 和每个槽位指向的实现。
  • 虚函数（CPlusPlusVirtualFunction）：实现自己有 C++ 名字就用它；没有（只剩 <redacted function N>）时，沿主基类链找同一槽位的名字，基类在别的镜像里也跟过去——进程内在进程里找，dyld shared cache 里在同一个 cache 里找，独立文件按调用方给的依赖搜索路径找。

现有的作用域树（CPlusPlusSymbolIndexStore）不变；两边的限定名用同一个解析器打印，调用方拿类名去作用域树里取非虚成员。纯新增 API，随本包 3.1.0 发布。

提议方案

  1. 新 store，放在现有 CPlusPlusSymbols 里。形状照 0005：.shared，方法带 in: machO，每个镜像第一次查询时建一次，缓存在驱逐组 .cPlusPlusClassStore 下。作用域树不动。
  2. 读指针分三条路。独立文件把链式 fixup 遍历一次（旧文件读 LC_DYLD_INFO 的 opcode）建表、用完即丢；cache 镜像逐槽按 cache 指针格式解码，不经带记忆的 resolveRebase(fileOffset:)；进程内直接读内存，用 InProcessContext.addressMask 去签名。
  3. 找 typeinfo：扫描加符号。数据段普通节里内容是「三个 __cxxabiv1 类 typeinfo 的 vtable + 16」的槽位，就是一个 typeinfo 的开头；再并入 __ZTI… 符号。
  4. 读 typeinfo。名字指针清 bit 63，名字串拼上 __ZTS 交给现有解析器；si 读一个基类，vmi 读标记与全部基类。外部基类记下符号名与来源库（文件）或地址（cache、进程内）。
  5. 找 vtable。指向本镜像某个 typeinfo、不在 typeinfo 对象里、前一格不是指针且在 [-2^31, 0] 内的槽位是 RTTI 格；之后逐格读到不是函数为止。
  6. 分组。相连、只隔着非指针格的同类表是一组；offset-to-top 为 0 的是主表。有 __ZTV 符号取它所在的组；没有符号又有多组时（只会是有虚基类的类，多出来的是 construction vtable）取地址最小的那组，记为已知局限。
  7. 副表归属。非虚基类按偏移递归展开，虚基类读主表前缀里的虚基类偏移；offset-to-top 等于负的子对象偏移的那个基类就是副表的主人。
  8. 槽位的名字。实现自己有名字就用；再沿主基类链取同一槽位的名字作为「基类函数」，并判断覆盖还是原样继承。槽位号超出基类表长的是类自己引入的虚函数。
  9. 跨镜像找基类。进程内按地址、cache 用 CacheImageLocator、独立文件用 FileDependencyLocator 并跟随 re-export；找到后在那个镜像上同样建索引，基类的基类也能继续找。
  10. 独立文件的搜索路径。通用方法默认用推断路径加本机 cache；@rpath 兄弟框架用带 dependencySearchPaths: 的重载显式给出。
  11. 发版：3.1.0，纯新增。

非目标

  • 类的字段（protobuf 另写提案；ObjC ivar 编码在下游合并）。
  • 非类的 typeinfo（指针、枚举、函数、数组、成员指针、基本类型）。
  • 把 RTTI 类并进 0005 的作用域树。
  • 没有符号时可靠区分自己的 vtable 与 construction vtable；VTT 的内容。
  • 反查某个函数出现在哪些 vtable 槽位。
  • 用 arm64e 槽位签名的判别值核对覆盖关系（推测，未验证）。
  • MSVC 的 RTTI；32 位 Mach-O；Linux 验证；下游采用。

详细设计

三个调用点 
// Simplest: the classes of an image, including the ones without symbols.
let store = CPlusPlusClassIndexStore.shared
let hiddenClasses = store.classes(in: machO).filter { !$0.hasTypeInfoSymbol }

// Most common: the virtual functions of a class, named through its bases.
if let cellID = store.class(named: "TST::CellID", in: machO) {
    for function in store.virtualTables(of: cellID, in: machO).first?.functions ?? [] {
        print(function.slotIndex, function.name?.demangledName ?? "?", function.baseFunction?.isInherited == false)
    }
}

// Most involved: a standalone file whose bases sit in an @rpath sibling.
let tables = store.virtualTables(
    of: cellID,
    in: tablesFile,
    dependencySearchPaths: [.machOFile(path: persistencePath), .systemDyldSharedCache]
)

公开类型 
public struct CPlusPlusClass: Hashable, Sendable, CustomStringConvertible {
    public let qualifiedName: String          // "TST::CellID", printed like CPlusPlusScope.qualifiedName
    public let scopePath: [String]
    public let baseName: String
    public let mangledTypeName: String        // "N3TST6CellIDE"
    public let typeInfoOffset: Int
    public let bases: [Base]
    public let inheritanceShape: InheritanceShape
    public let hasVirtualTable: Bool
    public let hasTypeInfoSymbol: Bool
    public let hasUniqueTypeInfo: Bool        // false for a hidden type on Apple arm64
}

extension CPlusPlusClass {
    public struct Base: Hashable, Sendable {
        public let qualifiedName: String
        public let mangledTypeName: String
        public let isVirtual: Bool
        public let isPublic: Bool
        public let offset: Int                // subobject offset; for a virtual base, the vbase-offset slot
        public let location: Location
    }
    public enum Location: Hashable, Sendable {
        case sameImage(typeInfoOffset: Int)
        case otherImage(installName: String?)
    }
    public struct InheritanceShape: OptionSet, Hashable, Sendable {
        public static let repeatedBase: InheritanceShape
        public static let diamond: InheritanceShape
    }
}

public struct CPlusPlusVirtualTable: Hashable, Sendable {
    public let addressPointOffset: Int
    public let offsetToTop: Int
    public let subobjectClassName: String?
    public let functions: [CPlusPlusVirtualFunction]
    public var isPrimary: Bool { offsetToTop == 0 }
}

public struct CPlusPlusVirtualFunction: Hashable, Sendable {
    public let slotIndex: Int
    public let implementation: Implementation
    public let symbolName: CPlusPlusSymbolName?
    public let baseFunction: BaseFunction?
    public var name: CPlusPlusSymbolName? { symbolName ?? baseFunction?.name }
}

extension CPlusPlusVirtualFunction {
    public enum Implementation: Hashable, Sendable {
        case function(offset: Int)
        case imported(symbolName: String, installName: String?)
        case otherImage(address: UInt64)
        case pureVirtual
        case deletedVirtual
    }
    public struct BaseFunction: Hashable, Sendable {
        public let className: String
        public let name: CPlusPlusSymbolName?
        public let isInherited: Bool
    }
}

  • classes(in:) 按限定名升序；class(named:in:) 遇到不同编译单元同名的 hidden 类时取 typeinfo 偏移最小的。
  • 通用的 virtualTables(of:in:)：进程内镜像在进程里找基类，cache 镜像在同一个 cache 里找，独立文件用推断路径加本机 cache。
索引的常驻内容与发现细节
  • 常驻：每个类的 CPlusPlusClass 值、vtable 组（address point、offset-to-top、所属子对象、槽位）、派生类下标；限定名与 typeinfo 偏移两张索引。槽位不存名字，查询时经作用域树的 symbols(for:in:) 取。外部基类的定位结果由 BaseClassLocator 按「根 + 搜索路径」缓存。槽位表建完即丢。
  • 扫描的节：__DATA* 与 __AUTH* 段的普通节，跳过 zerofill、__got、__auth_got、__la_symbol_ptr、__nl_symbol_ptr、__objc_*、__cfstring、__mod_init_func、__thread_*。
  • 三个 __cxxabiv1 vtable：文件看 bind 名与 addend 16；cache 在同一 cache 的 /usr/lib/libc++abi.dylib 导出表取地址；进程内 dlsym；镜像就是 libc++abi 时比自己的 rebase 目标。
  • typeinfo 的范围：class 16 字节、si 24 字节、vmi 24 + 16 × __base_count（超过 1,024 视为不是 typeinfo）。
  • 名字：清 bit 63 后读 C 字符串，拼 __ZTS 交给 CPlusPlusDemangler；解析不了的类仍收录，限定名用原样的修饰名。
  • 槽位是不是函数：本镜像目标在可执行节；bind 名不以 __ZTV、__ZTI、__ZTS、_OBJC_ 开头；别的镜像的目标在它的可执行段。
  • 主基类：第一个偏移为 0、非虚、带 vtable 的直接基类（「几乎为空的虚基类」当主基类的情况不处理）；递归深度上限 64。
  • 原样继承：同一镜像比偏移；导入比符号名；跨镜像一边在派生类镜像就是覆盖。
  • 线程安全：Storage 建成后不可变；定位器缓存用 NSLock。

Itanium ABI 布局与 Apple arm64 的非唯一 RTTI
  • libcxxabi/src/private_typeinfo.h：type_info 是 vptr 加名字指针；si 在 +16 放基类指针；vmi 在 +16 放 __flags（0x1 重复基类、0x2 菱形）、+20 放 __base_count、+24 起是基类条目（指针加 __offset_flags：0x1 虚、0x2 public、偏移在 >> 8）。
  • libcxx/include/typeinfo:144-181、:233：Apple arm64 上非唯一类型的名字指针 bit 63 置 1，比较时比字符串。只有 linkonce_odr / weak_odr 且默认可见性的类型（没有 key function 的类、模板特化）非唯一；hidden 的反而唯一（实现时由夹具测出）。
vtable 的形状（clang 21 探针）
  • 主表：[虚基类与 vcall 偏移……][offset-to-top = 0][RTTI][槽位……]；vptr 指向第一个槽位。
  • 多重继承：主表后紧跟副表 [offset-to-top = -16][RTTI，同一个类][thunk……]。
  • 虚继承：construction vtable __ZTC8Complete0_12Intermediate 的 RTTI 指向 Intermediate 自己的 typeinfo，是另一组独立对象。
  • 虚析构函数占两格；纯虚绑 ___cxa_pure_virtual，= delete 绑 ___cxa_deleted_virtual。
本包现有的基础设施
  • MachOKit 的 MachOFile.resolveBind(at:)（MachOFile.swift:927-950）每次都把所有链式指针列一遍；逐槽调用是平方级，所以自己遍历一次。
  • MachOAddressResolution：SlotResolver（只收 MachOFile）、ImageAddressSpace、CacheImageLocator；cache 镜像的 offset 是「未滑动地址减 sharedRegionStart」。
  • MachODependencies：FileDependencyLocator.locate(loadName:)；@rpath 不展开，兄弟框架要显式给 .machOFile(path:)。
  • MachOReading：InProcessContext.addressMask 去掉进程内指针的签名与 tag。
  • 测试包二进制是链式 fixup 还是 opcode：未查证，第 1 步先确认。

替代方案

6 条被否的路
  • 只用 __ZTI / __ZTV 符号：TSTables 的 167 个无符号类恰好是最需要恢复的。
  • 逐槽调用 SlotResolver 或 resolveBind(fileOffset:)：平方级，且带记忆的版本会让每个槽常驻。
  • 并进 0005 的作用域树：建树要多读数据段，两份索引的成本与种类判断会绑在一起；先分开。
  • 只在本镜像内补名：TSTables 434 个类的基类在 TSPersistence；用户选择跨镜像。
  • 字段一起做：ObjC 编码只能在下游合并且几乎不重叠；protobuf 是另一套格式。用户选择另写提案。
  • 只用测试包自己的二进制测试：给不出剥离后的无名槽位与 @rpath 跨镜像基类；改用预编译的小 dylib。
