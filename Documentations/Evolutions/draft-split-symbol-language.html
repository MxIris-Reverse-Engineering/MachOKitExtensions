摘要

本包的 SymbolLanguage 只认 C 与 C++。.swift 与 Swift 名字的判断搬到 MachOSwiftSection 的 SwiftSymbols，.objectiveC 与 Objective-C 名字的判断搬到 MachOObjCSection。SymbolLanguage 改成能从外部扩展的字符串类型（照 Notification.Name），本包新增进程级的 SymbolLanguageRegistry：别的包在自己的镜像被 dyld 加载时，由一个 C target 的 constructor 注册自己的语言和识别闭包。名字的语言按「C++ → 已注册的语言（按注册顺序）→ C」判定。

SymbolIndexStore 只收 C 与 C++ 的名字；已注册语言的名字只留下偏移作为边界，地址落在别的语言的代码里时 closestSymbols 答 nil，不再答前面一个不相干的 C 符号。索引建好之后才有新语言注册时，已建的索引作废、下次查询重建。这是破坏性改动，与 C++ 符号的结构化归类一起发本包 3.0.0，MachOSwiftSection 与 MachOObjCSection 同日各发新版。

要你定

已批准（2026-11-19），实现中

  1. 三个仓库各开 feature/split-symbol-language，按落地步骤实现；落地等 C++ 结构化归类的提案，一起发 3.0.0。

写提案时自己定的（可推翻）

  • 注册表是带 .shared 的类，API 为 register(_:where:)；测试用独立实例。
  • 同一语言重复注册保留第一次的识别器；注册 .c、.cPlusPlus 视为程序员错误。
  • Swift 索引直接用自己的判断，不经注册表。
  • 索引记下注册表代数，查询时不符就重建；.shared 上注册时另外立即清空。
  • SymbolOffsetIndexing 新增 .sortedOffsetsOnly；ObjC 的 constructor 放进已有的 MachOObjCSectionC。

详细设计

本包：SymbolLanguage 
public struct SymbolLanguage: RawRepresentable, Hashable, Sendable, CustomStringConvertible {
    /// The language's name as a person reads it — "C", "C++", "Swift".
    public let rawValue: String
    public init(rawValue: String)

    public static let c = SymbolLanguage(rawValue: "C")
    public static let cPlusPlus = SymbolLanguage(rawValue: "C++")
    public var description: String { rawValue }

    public init(ofSymbolNamed name: String, registry: SymbolLanguageRegistry = .shared)
    @_spi(Internals)
    public init(ofSymbolNameBytes name: UnsafePointer<CChar>, registry: SymbolLanguageRegistry = .shared)
}

SymbolLanguage(ofSymbolNamed: "__ZN4llvm5Value4dumpEv")   // .cPlusPlus
SymbolLanguage(ofSymbolNamed: "_malloc")                  // .c
SymbolLanguage(ofSymbolNamed: "$s7SwiftUI4TextVMn")       // .swift when SwiftSymbols is linked, .c otherwise
本包：SymbolLanguageRegistry 
public final class SymbolLanguageRegistry: Sendable {
    public static let shared = SymbolLanguageRegistry()
    public init()

    /// A name `recognizes` accepts is `language` from now on, unless C++ mangling
    /// or a language registered earlier claims it first. On the shared registry,
    /// every index SymbolIndexStore.shared built before is dropped.
    public func register(
        _ language: SymbolLanguage,
        where recognizes: @escaping @Sendable (UnsafePointer<CChar>) -> Bool
    )

    public var registeredLanguages: [SymbolLanguage] { get }
}
  • 内部存识别闭包数组与代数，由一把 NSLock 保护（本包最低 macOS 10.15，用不了 Mutex）。
  • SPI 的快照是值类型：持有闭包数组的拷贝与当时的代数；先判 C++，再依次问闭包，都不认领返回 .c。采集开始时取一份，循环里不碰锁。
  • 重复注册同一语言保留第一次的识别器（同一个包可能被两个镜像各带一份）；注册 .c、.cPlusPlus 触发 precondition。
本包：采集与 .sortedOffsetsOnly 
extension SymbolOffsetIndexing {
    /// No rows: only every canonical offset a name is filed under, ascending.
    public static let sortedOffsetsOnly: SymbolOffsetIndexing
}

extension SymbolSweep {
    public init(
        sweeping machO: some MachORepresentableWithCache,
        routing: Routing,
        languageRegistry: SymbolLanguageRegistry = .shared

  • .sortedOffsetsOnly 的表：symbolTable、rowsByOffset 为空，hasLocalSymbols 为 false；导出表一路不登记它；调试条目与文件的原始符号值不进偏移。
  • 每个名字多一次闭包调用；落地步骤 3 量一次 AppKit 的建索引耗时，与 2.0.0 对比后记进实现说明。
本包：SymbolIndexStore 
struct CAndCPlusPlusSymbolTableRouting: SymbolTableRouting {
    enum Table: Hashable, Sendable { case symbols, boundaries }

    func table(forSymbolNamed name: UnsafePointer<CChar>, language: SymbolLanguage) -> Table? {
        language == .c || language == .cPlusPlus ? .symbols : .boundaries
    }

    func offsetIndexing(in table: Table) -> SymbolOffsetIndexing {
        switch table {
        case .symbols: .byOffsetWithSortedOffsets
        case .boundaries: .sortedOffsetsOnly
        }
    }

    var mayReferenceStringTablesOfLoadedImages: Bool { false }
}
  • closestSymbols：在两张表里各找不大于目标的最后一个偏移 s、b；b 存在且大于 s（或没有 s）时答 nil；同一偏移两边都有时答 C/C++ 符号。
  • 按名字、按精确偏移、是否导出的查询只看 .symbols。
  • Storage 记代数，storage(in:) 取到旧代数的索引先 remove(for:) 再建；.shared 上注册时另外 removeAll()。

调研

动机
  • 本包硬编码了两门不归它管的语言。 SymbolLanguage.swift:78-115 按前缀判断 Swift 与 Objective-C；Swift 的前缀表要和 swift-demangling 的 isSwiftSymbol 一致，只能靠 MachOSwiftSection 的测试跨包钉住。改任何一门语言的规则都得改本包、发本包的版本。
  • 类型号称可扩展，别的包却扩展不了。 内部是私有的 Kind 枚举、构造方法私有，别的包造不出新值。
  • 用户的决定：语言的定义和判断归各自的包，本包只处理 C 与 C++。
  • 顺带修掉 2.0.0 已有的错答：C/C++ 索引不收 Swift 名字，地址落在 Swift 函数里时 closestSymbols 答出前面某个不相干的 C 函数；把 ObjC 也排除后 ObjC 方法同样会错答，所以一并给出边界。
现状、使用方与版本约束
  • SymbolSweep 的三条采集路径（SymbolSweep.swift:63、:101、:124）对每个名字判一次语言；C/C++ 索引的 routing NonSwiftSymbolTableRouting 收 .swift 以外的一切。
  • SharedCache.removeAll()（SharedCache.swift:141）能一次清掉一个 store 的全部镜像；本包统一用 NSLock。
  • 使用方：MachOSwiftSection 的 SwiftSymbolTableRouting.swift:18-21 与两个测试用 .swift；.objectiveC 只在本包测试里用；MachOObjCSection 不依赖 MachOSymbols；RuntimeViewer、MachOKitUI、swift-decompiler、REAgent 都没用。
  • 版本：MachOSwiftSection 0.25.0 from: "2.0.0"，MachOObjCSection 0.8.207 "2.0.0"..<"3.0.0"，RuntimeViewer next from: "2.0.0"。0.25.0 的 Swift 索引靠本包判出 .swift，2.x 里不判了它会悄悄变空，所以只能 3.0.0；同名静态成员会产生歧义，也留不了废弃过渡。
  • 工具链：本包与 MachOObjCSection 是 6.2，MachOSwiftSection 是 6.3；SE-0495（@c）与 SE-0492（@section）都在 6.3 实现；MachOObjCSection 已有被主模块依赖的 C target MachOObjCSectionC。
原型（2026-11-19，Swift 6.4.2 / Xcode 27.2）
  • C target 的 constructor 调用 Swift 的 @c 函数：可行。 探针程序不引用注册模块的任何符号，swift build 的 debug、release 与 xcodebuild Release 三种都在加载时拿到了注册。
  • 纯 Swift 用 SE-0492 把闭包放进 __mod_init_func：链接失败。 ld: fixup error (kind=arm64_adrp_lo12) … ADRP out of range … to 0x00000000，改成 private 也一样。推测是新链接器把这个 section 改写成 __init_offsets，而编译器生成的访问器仍引用原地址。
  • ObjC 的 +load：没有测，C constructor 已够用。原型代码已删除。
先例与非目标
  • 先例：Notification.Name、NSAttributedString.Key（以字符串为 rawValue、别的模块扩展静态成员）；URLProtocol.registerClass(_:)、AppDependencyManager.shared（进程级注册）；谓词闭包的标签用 where:。
  • 非目标：C++ 结构化归类（另写提案，同日落地）；ObjC 符号索引与 ObjCExportIndex 改写；SwiftSymbolIndexStore 的行为；撤销注册；本包代别人注册其他语言；在 Linux（ELF）上验证。

替代方案

11 条，均已否决
  • 不认识的都算 C：结果确定，但索引会收进别的语言的名字。用户否决。
  • 按 C 语法正面识别：_open$NOCANCEL、_OBJC_CLASS_$_… 这类边界难划。用户否决。
  • 调用方启动时显式注册：忘了就悄悄判错。
  • 各包在入口第一次被用到时注册：生效时机取决于调用顺序。
  • 纯 Swift 用 @section 写进 __mod_init_func：实测链接失败。
  • ObjC 的 +load：要 Objective-C 运行时；C constructor 已实测可行。
  • 晚注册不处理 / 直接 precondition 失败：前者留下旧索引，后者在 dlopen 插件这类合理场景里崩溃。
  • 被排除的名字完全不收：closestSymbols 会在别的语言的代码里错答。
  • 拆分单独发 3.0.0：三个仓库短期内要再切一次大版本。
  • 本包保留废弃的 .swift / .objectiveC 过渡一版：与下游扩展里的同名成员冲突，做不到。
  • 注册表做成静态方法 / 识别器做成协议：前者测试没法用独立实例；后者目前一个闭包就够。

影响

有破坏，本包发 3.0.0

  • .swift、.objectiveC 不再在 MachOSymbols 里，要多 import SwiftSymbols / MachOObjCSection。
  • 进程里没链接这两个包时，Swift 与 ObjC 名字判成 .c，并进 C/C++ 索引（例如 MachOKitUI 关掉 SwiftSection trait 的构建）。
  • closestSymbols 在别的语言的代码里答 nil，以前答前面一个 C 符号。
// Before (2.x)
import MachOSymbols
if SymbolLanguage(ofSymbolNamed: name) == .swift { … }

// After (3.0.0)
import MachOSymbols
import SwiftSymbols            // defines .swift and registers it at load
if SymbolLanguage(ofSymbolNamed: name) == .swift { … }
  • ABI：不适用 —— 本库以 SPM 源码分发，使用方每次重新编译。
  • 下游：MachOSwiftSection、MachOObjCSection 同日发新版；RuntimeViewer next 落地当天把本包下限改为 3.0.0；swift-decompiler 落地当天编译确认；MachOKitUI、REAgent 暂不受影响。
  • 文档：本包 README.md 与 Internal/SymbolIndex.md；MachOSwiftSection 的 SwiftSymbols 文档与术语表；MachOObjCSection 的说明。
  • 演进：不留废弃期；rawValue 字符串成为语言的身份，以后改名即破坏；register(_:where:) 的闭包签名发布后不改，要加能力时新增接收协议的重载。
