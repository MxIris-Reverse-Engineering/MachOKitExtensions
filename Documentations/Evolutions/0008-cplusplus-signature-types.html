摘要

CPlusPlusSymbolName 新增 parameterTypeReferences 与 returnTypeReferences：参数文本与返回类型文本里每个命名类型的作用域路径，以及它在文本里的范围（Range<String.Index>）。位置在打印文本的同一次遍历里从 AST 节点记下，调用方不必解析打印出来的文本。同时修一处漏判：局部实体的外层不带参数时（ObjC++ 里 ObjC 方法的局部静态变量，Z 26-[CAMetalDrawable texture] E 9onceToken），外层也是函数作用域，不再落成「未定」。纯新增 API 加一处行为修正，随 3.3.0 发布。

没有待定的事

用户选定在本包加接口、发 3.3.0，而不是在 RuntimeViewer 里解析参数文本。

详细设计

extension CPlusPlusSymbolName {
    public struct TypeReference: Hashable, Sendable {
        public let path: [String]
        public let range: Range<String.Index>
    }
    // public let parameterTypeReferences: [TypeReference]
    // public let returnTypeReferences: [TypeReference]
}
  • 哪些算类型：与「当作类型用到」同一套判定（forEachNamedType）：命名类型记下并进入它的模板实参，指针、引用、函数类型继续往里走，遇到表达式就停。
  • 限定词不单列：记下一个类型后，到它打印完不再记别的节点；进入模板实参表才重新记。both(CA::Foo, CA::Foo::Bar) 得两项。
  • 排序：按起点升序，起点相同外层在前；范围只嵌套、不交错。
  • 回头改写：notifyInsertion 挪动范围，notifyDeletion 丢弃越界的范围。
  • 代价：随 CPlusPlusSymbolName 一起算；建作用域树不构造它，不受影响。

调研

打印钩子、回头改写、名字复用、ObjC 方法的局部名
  • OutputBuffer 的虚函数 printLeft/printRight 与 notifyInsertion/notifyDeletion；子节点打印都经过钩子（直接 16 处、经 print 72 处）。Node::printLeft 私有，派生类调 OutputBuffer::printLeft。
  • insert 与 setCurrentPosition 回退会改动已打印的文字。
  • 替换让同一节点多处出现：S0_ 在 CA::Foo::Bar 里复用 CA::Foo。
  • _ZZ26-[CAMetalDrawable texture]E9onceToken 的 encoding 是不带参数的 NameType；文法上 Z … E 的外层总是函数。

替代方案

  • 下游解析参数文本：本包有 AST，否决。
  • 公开 referencedTypePaths 让下游去文本里搜：位置靠搜索会错位，否决。
  • 返回带标注的文本：本包不定义展示类型，范围加路径更中性。

影响

  • 源码兼容：纯新增；ObjC 方法一类外层的 kind 从 .undetermined 变成 .function。
  • ABI：不适用，SPM 源码分发。
  • 下游：RuntimeViewer 抬到 3.3.0，参数与返回类型里的类型着色并可跳转，QuartzCore 不再列出以 ObjC 方法命名的命名空间；MachOSwiftSection、MachOObjCSection 不受影响。
  • 版本：semver minor，3.3.0。
